# Goal 3: Directional Causality and Backpressure-Aware Root Cause Analysis

## 1. Problem with Naive Root-Cause Selection
In a microservices architecture, a failure in one service (e.g. `ts-train-service`) often propagates downstream to its callers (e.g. `ts-route-service`, `ts-ui-dashboard`). If the root cause analysis naively selects the service with the highest anomaly score or highest critical probability, it may incorrectly identify a downstream victim rather than the true upstream root cause.

## 2. Directional Causality
To solve this, Goal 3 introduces a topological and temporal causal model using the discovered service graph (from Goal 2). 
- **Parent**: The upstream service receiving the request (the dependency).
- **Child**: The downstream service sending the request (the caller).

If a parent fails, it affects the child. Therefore, the direction of causal influence flows opposite to the direction of request dependency. We track this explicitly.

## 3. Temporal Ordering
A strong indicator of causality is temporal precedence. We track the `degradation_start_tick` for each service.
- If service A (parent) degrades at tick T, and service B (child) degrades at tick T+1, it is highly likely that A caused B's degradation.
- If service C (child) degrades while service A (parent) is healthy, C's degradation cannot be attributed to A.

## 4. Backpressure Detection
When available, we incorporate the request volume between services (`istio_requests_total`) to strengthen the causal edge. A higher request volume indicates a stronger coupling and higher likelihood of backpressure propagation.

## 5. Root-Cause Scoring
The `DirectionalCausalAnalyzer` computes three primary scores:
- **Intrinsic Evidence**: Based on the service's own anomaly score and health posteriors.
- **Upstream Causal Evidence**: The amount of downstream degradation that this service explains, weighted by temporal precedence and backpressure.
- **Victim Evidence**: The amount of degradation in this service that is explained by an upstream parent's earlier degradation.

The final root cause score is:
`RootCauseScore = IntrinsicEvidence + UpstreamCausalEvidence - VictimEvidence`

## 6. Propagated Victim Concept
Based on the relative weights of the above evidence, the analyzer classifies services into:
- **ROOT_CAUSE**: High intrinsic evidence, high upstream causal evidence, low victim evidence.
- **PROPAGATED_VICTIM**: High victim evidence from an upstream parent.
- **NORMAL**: Healthy or negligible anomalies.

## 7. Integration with DBN
The `DirectionalCausalAnalyzer` is integrated directly into `DynamicDecisionNetworkPhase3` (and `DynamicDecisionNetwork`). After the particle filter calculates state posteriors for the current tick, the analyzer steps forward, calculates the causal metrics, and overrides the naive localization algorithm. The expected utility and intervention logic remain intact.

## 8. Integration with Goal 2
The module directly reads the `data/experiments/discovered_service_graph.json` generated by Goal 2, ensuring that the causal logic operates on actual, observed runtime dependencies rather than hardcoded edges.

## 9. Test Scenarios
We validate the logic against multiple scenarios:
- **Test 1**: Independent anomaly correctly localized.
- **Test 2**: Upstream failure propagation correctly localized.
- **Test 3**: Three-level propagation correctly localized.
- **Test 4**: Downstream-first anomaly avoids false attribution.
- **Test 5**: Recovery appropriately decreases victim scores.

## 10. Limitations
- The temporal logic depends on the tick resolution (currently 1 minute). If multiple services fail within the same minute, the causal order relies entirely on topological structure rather than precise millisecond-level precedence.
- The backpressure logic currently relies on total request counts.

## 11. Future Extensions
The model can be extended by incorporating:
- **Memory Pressure**: Directly penalizing intrinsic evidence if OOM kills are detected.
- **Latency / Error Rate**: Utilizing Istio's HTTP error codes (e.g. 503) or tail latency on specific edges to build stronger causal evidence.
